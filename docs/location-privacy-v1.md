# V1 location boundary

- **Private address**: `privateUserAddresses/{uid}` is an owner-only account record. It is never read by listing creation, discovery, seller projection, or metadata.
- **Public general location**: a listing has `publicLocation: {districtOrCity, state, country: "Malaysia"}` plus a derived, general-only `location` string for existing search/analytics consumers. `privacyVersion: 2` marks server-validated documents. No precise coordinates or address fields are written. Public listing queries filter to version 2; legacy drafts are owner-only until corrected.
- **Public discovery**: Admin-SDK-backed recommendation, similar-listing, and featured-promotion responses also refuse legacy/unsafe listing documents. Profile location used in discovery titles is parsed as a general city/state only; legacy address text is ignored.
- **Meet-up locations**: `users/{uid}/meetupLocations/{id}` is owner-managed. A seller explicitly selects one for a listing. The server verifies ownership and snapshots only the place name and general area onto the listing. The Settings UI warns that removing a saved place does not change existing listing snapshots; sellers must edit those listings separately.

- **Public collection boundary**: Direct Firestore listing collection queries are seller/admin-only. Public Home, Explore, and seller listing rails call `getPublicListingPage`, which rejects unsafe source documents and returns an explicit field allowlist. Public document `get` still requires `publicListingSafe`.
- **Seller-authored content**: Listing titles and descriptions are user-generated public content. A seller may type an address there; TAKEME does not claim this text is address-free. Structured private address fields are never used to compose listing titles, descriptions, social previews, or public-list results. Social descriptions use the validated general area rather than the seller-authored description.

Server callables validate both fixed-price and auction creation/update and refuse to publish drafts without valid general location. A private address is never a default meet-up place. Metadata does not reuse seller-authored description text. Listing photos are re-encoded before upload to avoid retaining embedded image metadata.

Legacy draft migration is deliberately separate. `scripts/migrate-draft-listing-location.mjs` requires explicit listing IDs and seller-confirmed city/state mappings; it defaults to a redacted dry run. It never touches active listings or user addresses. Applying it requires separate approval and `--apply --approve=takeme-52b80`. Uncertain locations must be corrected by the seller, not guessed. Deploy the new composite indexes before any client querying `privacyVersion: 2`; coordinate Functions, rules, and web rollout separately.

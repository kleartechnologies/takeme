## Concurrency and limits

Retain 2 CPU, 2 GiB, concurrency 1, min 0, service and revision max 2, request timeout 90 seconds. One untrusted decode/container preserves the existing memory/kill boundary; max 2 supplies bounded cross-instance parallelism. Client photos already admit/upload concurrently. Two local workers demonstrate possible batch savings but do not establish worst-case memory safety for two large/native adversarial decodes in one container. Do not raise concurrency/min instances or rewrite queue policy blindly. Keep 30 MiB input, 50 million pixels, 16,384 edge, 8 photos, 60 MiB queued frontend input and existing rate/quota/idempotency controls.

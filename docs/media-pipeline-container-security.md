## V1 without HEVC — current qualification, 2026-10-08

This addendum supersedes the historical HEVC runtime/deployment conclusions below. Historical scans and codec qualification remain preserved for V1.1.

- Exact local runtime image: `sha256:cc4c1051c6ff58a86efe180dfb05e5af728ac4b8cca5451911b2689df285bbc8`; local image size 123,584,447 bytes. Fresh Trivy scan: **0 CRITICAL / 47 HIGH / 67 MEDIUM / 75 LOW / 3 UNKNOWN**. Every HIGH package/advisory/version tuple matches the reviewed Trixie findings below. No suppression was introduced; PASS is a bounded reachability disposition, not zero vulnerabilities.
- Node 22.23.0, Sharp 0.35.5, libvips 8.18.7 (HEIF disabled), libavif 1.4.2, Debian dav1d 1.5.1-1 and libyuv 0.0.1904.20250204-1. libheif/libde265/x265/HEVC are absent from runtime files, installed packages and decoder closure. Sharp has no HEIF loader. Raw HEIC/HEIF is rejected before native decode, as well as at admission.
- The only added executable boundary is the fixed absolute `/usr/local/bin/avifdec` inside the existing disposable Node child. It uses the dav1d AV1 decoder only, one decode thread, 50-million-pixel/16,384-edge limits, a 20-second hard kill and 0600 temporary inputs removed in `finally`. The outer decoder hard-kills after 45 seconds. No caller-controlled binary/options, shell, document/XML, privileged mount/ACL/terminal/Perl path or HEVC fallback was introduced. Existing HIGH reachability exclusions remain applicable to both Node and the inspected avifdec dynamic closure.
- [libavif 1.4.2 upstream release](https://github.com/AOMediaCodec/libavif/releases/tag/v1.4.2) and pinned source/CLI were reviewed separately from distro scanning. Native-source builds are not fully inventoried by Trivy. Version 1.4.2 applies AVIF orientation/crop transforms; orientation and alpha tests pass. No security fix is inferred solely from switching codecs.
- Three UNKNOWN-severity entries remain visible: [CVE-2026-77214 / Expat](https://security-tracker.debian.org/tracker/CVE-2026-77214) requires the excluded untrusted XML parser path; [CVE-2026-82560 / Perl Pod::Text](https://security-tracker.debian.org/tracker/CVE-2026-82560) requires POD formatting, which the service never invokes; [Debian TEMP-1147318-639065 / liblzma](https://security-tracker.debian.org/tracker/TEMP-1147318-639065) is reported by Trivy but the installed 5.8.1-1+deb13u2 is marked fixed by Debian. liblzma is also absent from Node/Sharp/avifdec dynamic closure. These are explicit dispositions, not scanner suppressions or a decision to treat UNKNOWN as safe by default.
- Exact-image processor runtime with baked regression tests: **15/15 PASS**, including malformed JPEG/PNG/WebP/AVIF, raw HEIC brands, MIME spoofing, excessive dimensions, GPS/EXIF removal, AVIF orientation/alpha, immutable outputs and duplicate/generation handling. Fresh merged Functions/Firestore/Storage emulator integration also passes with this image. Current no-HEVC staging revision `takeme-media-v1-00005-rkq` passes real Eventarc supported-format, batch, stripping and permit checks; final physical iPhone acceptance is owner-confirmed PASS for Safari-supplied supported representations; Android remains UNVERIFIED/non-blocking. The previous HEVC staging revision is retained only as historical evidence.
- Non-root execution, stripped SUID/SGID, fixed subprocesses and scrubbed environment do not isolate the Cloud Run metadata identity. Dedicated conditional Storage IAM and minimal Firestore/Auth roles remain mandatory. No production IAM or deployment was applied.

Current scope and remaining release gates: [V1 without HEVC](media-pipeline-v1-no-hevc.md).

## Evidence and boundaries

- Fresh scan, package list, dynamic `ldd` closure, image identity, build output and XML call-site inspection are preserved privately outside Git. No missing runtime libraries; zero SUID/SGID paths after stripping. Processor tests cover nonimage/XML/native VIPS rejection, real pixel decode, GPS/EXIF stripping and safely rejected bad-seek HEIC fixture.
- [Pinned libvips native XML reader](https://github.com/libvips/libvips/blob/v8.18.7/libvips/iofuncs/vips.c) and `normalize.mjs` show the relevant boundary. [Debian Expat advisory](https://security-tracker.debian.org/tracker/CVE-2026-76957) documents the custom-encoding callback prerequisite; the other Expat issues also require untrusted XML parsing, excluded here. These findings remain visible and must be patched when stable updates become available.
- [libheif 1.23.6](https://github.com/strukturag/libheif/releases/tag/v1.23.6) is a security release included in the pinned build. Decoder source checksums are verified before compilation. No x265 encoder or FFmpeg dependency is included. No known reachable critical/high codec finding was identified in this assessment; this is not exhaustive fuzzing assurance.
- Decode runs as a non-root disposable Node subprocess with fixed byte/pixel/edge limits and a hard 45-second kill. Clearing credential environment does **not** block Cloud Run metadata identity access. Cloud IAM is a separate mandatory gate, not passed by a zero-critical scan.
- The container reachability disposition passes for this exact narrow photo-input interface. **Production deployment remains blocked by commercial HEVC review and outstanding browser/phone/cloud qualification. The exact staging-only image and IAM scope are recorded in the resumed qualification document.** Any new input format, native library, execution path, privileges or service identity requires requalification.
